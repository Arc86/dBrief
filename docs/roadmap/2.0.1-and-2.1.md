## How to work here

- Build: `swift build`; tests: `swift test` (≈2,240 tests, Swift Testing). Beta app: `make run-beta` (one beta at a time; it shares settings with any other running beta).
- UI strings go through the string catalog (`String(localized:)` for strings that travel as `String`; see CLAUDE.md "UI strings"). After adding strings run `make strings` (needs Xcode) and add Dutch entries; `make strings-check` must pass (CI checks it).
- CI runs on PRs and main only. Every push to a PR cancels the running CI (about 23 min end to end).
- Auto-mode blocks `gh pr merge` and direct pushes to `main`: open a PR and let Jesper merge.
- Release notes collect in `tasks/release-notes-pending.md` (local, untracked) under `## dBrief 2.0.1`. User-facing items only.
- One branch per item, or small related groups; PR into `main` (or into `release/2.0.1` if Jesper wants a release branch PR). Bump `Info.plist` to 2.0.1 only when releasing.

## 2.0.1 — patch release

### Fixes and small polish

1. **Call prompt: "Don't ask for this app"** (requested by Jesper)
   - Add an action on the call-detected prompt that stops prompting for that app: it inserts the app's bundle id into `AppSettings.disabledCallApps` (`Sources/dBrief/App/AppSettings.swift:916`), which `CallDetectionService` already honours (`Services/CallDetectionService.swift:219`).
   - Browser calls are detected as "Web call (<browser>)" (`CallDetectionService.swift:192/246`). Make sure such browser entries appear in **Settings → Meetings → Apps to watch** so a muted one can be turned back on there.
   - Prompt UI: `UI/CallDetectedPopup.swift` (+ `CallDetectedOverlayController`). Keep it keyboard reachable and announced (the prompt already has VoiceOver support); localize new strings (EN + NL).
   - Done when: choosing it hides the prompt, the next call from that app doesn't prompt, and the app shows as off in Apps to watch with a working toggle. Unit-test the pure part (which id gets stored for a native app vs a browser call).

2. **Bug: stray transcript file after rename + delete**
   - Renaming a speaker and deleting the recording right after can write `<base>.richtranscript.json` back after the delete. The enrollment/rename task calls `saveTranscript` without checking the recording still exists (`UI/TranscriptWindowView.swift` around the `saveTranscript` calls, ~1376–1435).
   - Fix: cancel the view's pending transcript tasks on delete, or skip the write when the audio is gone. Add a test where possible (the delete path is `RecordingManager.deleteRecording`).

3. **Launch speed: Keychain on the main thread**
   - `KeychainHelper` (`Utilities/KeychainHelper.swift`) reads integration tokens during `AppSettings.init` on the main thread: ~0.24 s at launch, ~20 s when a Keychain prompt blocks.
   - Measure first (Instruments / signposts), then load tokens lazily or off the main thread without changing behaviour for integrations. Tests already keep secrets in memory (test host), so add a test for the lazy path.

4. **Accessibility follow-ups** (issue #100)
   - A real VoiceOver + Keyboard-navigation pass in the beta of the 2.0 accessibility work (recording controls, call prompts, speaker review, viewer, library, onboarding, Settings). Record findings; fix the majors.
   - Known leftovers: the hidden Transcript tab still takes a Tab stop (disabling it re-rendered every row, so it was left; find a cheap way), and the voice-library merge sheet's target list has no arrow-key navigation.
   - Increase Contrast support (audit item XC-04) was deferred to "Part C"; include only if small.

5. **Dutch review**
   - All Dutch strings are machine drafts marked `needs_review` in `Sources/dBrief/Resources/Localizable.xcstrings`. Jesper (native speaker) reviews; the agent's job is to make that easy (e.g. export a reviewable list grouped by screen, apply his corrections, mark reviewed) and to check layouts with `open dBrief-Beta.app --args -AppleLanguages "(nl)"`.

6. **Chat header shows the answering engine** (small)
   - The Ask dBrief AI header subtitle says "This recording"; show the engine that answers, e.g. "This recording · Gemma, on-device" (`UI/ViewerAssistantPanel.swift`, `UI/TranscriptChatView.swift`). Localize.

### Engineering hygiene

7. **CI speed** (`.github/workflows/ci.yml`): cache `.build` between runs (`actions/cache` keyed on `Package.resolved` + Swift version), and build/upload the beta package only on pushes to `main`, not on PRs. Expected saving: 10–20 min per PR run. Keep the editor-bundle and strings checks.
8. **Flaky tests under load:** `Tests/dBriefTests/FFmpegProcessRunnerTests.swift` and `PromptAsyncSessionTests.configurationChangePermanentlyInvalidatesSuggestion` have hung (>1 h, 100 % CPU) while the machine was busy; they pass alone. Diagnose with `sample <pid>` on a hung run (see the earlier fix for `PrivacyHTTPTraceTests`: `Process.waitUntilExit()` from a test task can miss the exit event).
9. **Bluetooth earbuds sometimes start silent** when recording starts or the mic switches (mic switching design: CLAUDE.md "Microphone sources and device switching"). Needs a hardware pass by Jesper (Bluetooth → Mac mic → Bluetooth, case in/out, pause/resume) and logs from the beta.
10. **Live chat carry-over:** verify that a chat started during a live recording carries over when the recording finishes (`TranscriptChatService.rebind`, `TranscriptWindowView.setTranscript`); never confirmed interactively.

## 2.1 — next minor release (bigger; propose a design before building)

1. **More UI languages: German, French, Spanish.** Same pipeline as Dutch (localization plan phase 6): add to `CFBundleLocalizations`, draft translations, layout pass with `-NSDoubleLocalizedStrings YES`, guardrails already in CI. Also widen the AI "Results language" picker (`OutputLanguage`) with the same languages. Each language needs a native reviewer.
2. **Library icon rail + Settings on the flat sidebar.** Collapsed library sidebar becomes a ~72 pt icon rail (toggle, search, smart views, Record, Settings); Settings uses the same flat full-height sidebar as the library, fixed ~236 pt, never collapses; one shared header/search/row component. Key files: `ViewerLibraryLayout`, `ViewerLibrarySidebar`, `SettingsView`, `SettingsSidebar`. Decisions to confirm with Jesper: rail width, rail contents, one header mark for both windows, shared row metrics.
3. **Progress bar for local AI analysis.** Transcription already has a determinate bar + ETA; analysis shows a spinner. Options: time-based ETA from `ModelPerformanceStore` averages (consistent, can be off), Gemma token-stream progress (accurate for Gemma only), or an indeterminate bar. Must not fight the model download/load progress. Step rendering is already generic in `TranscriptionProgressView`.
