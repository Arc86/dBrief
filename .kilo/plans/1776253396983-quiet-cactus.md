# Plan: Cleaner Transcript Format for LLM Processing

## Problem

When using WhisperKit for local transcription, the `formatWhisperTimestampTokens()` method embeds inline timestamp markers like `**[00:00]**` throughout the transcript text. This significantly increases token count when sent to LLMs for analysis.

Example of current LLM input:
```
**[00:00]** Hello everyone **[00:05]** Welcome to the meeting **[00:12]** Today we're discussing...
```

## Root Cause

In `WhisperKitTranscriptionService.swift`, the `cleanTranscriptArtifacts()` method at lines 322-335 calls `formatWhisperTimestampTokens()` which converts WhisperKit's native `<|123.45|>` tokens into formatted `**[MM:SS]**` markers embedded inline in the transcript text.

## Solution

Create a dedicated "LLM-friendly" transcript format that strips timestamps and provides speaker context in a compact form. Remote endpoints that don't support diarization will get raw text only.

### Format: Speaker + Speech (Default for WhisperKit with Diarization)
```
Speaker 1: Hello everyone
Speaker 2: Welcome to the meeting
Speaker 1: Today we're discussing the project
```

### Format: Raw Text Only (For Remote Endpoints without Diarization)
```
Hello everyone Welcome to the meeting Today we're discussing the project
```

## Implementation Plan

### 1. Add Computed Property to TranscriptionResult

**File:** `Sources/dBrief/Models/TranscriptionResult.swift`

Add a computed property `textForLLM` that returns a clean format without timestamps:

```swift
var textForLLM: String {
    if segments.isEmpty {
        return text.replacingOccurrences(of: #"\*\*\[\d{2}:\d{2}:\d{2}\]\*\*"#, with: "", options: .regularExpression)
    }
    let hasSpeakerInfo = segments.contains { $0.speaker != nil }
    if hasSpeakerInfo {
        return segments.map { segment in
            if let speaker = segment.speaker {
                return "\(speaker): \(segment.text)"
            }
            return segment.text
        }.joined(separator: "\n")
    }
    return segments.map { $0.text }.joined(separator: " ")
}
```

The logic:
- If segments have speaker info → use "Speaker: speech" format
- If segments exist but no speakers → use raw concatenated text
- If no segments → strip timestamp markers from original text (fallback for legacy/custom transcripts)

### 2. Update AI Services to Use Clean Format

Update these files to use `transcription.textForLLM` instead of `transcription.text`:

- `Services/AIService.swift` - all methods (generateSummary, extractActionItems, analyzeTags, generateTitle)
- `Services/LocalAIService.swift` - all methods
- `Services/MLXInsightsService.swift` - buildUserPrompt()
- `Services/RecordingManager.swift` - all AI task calls (lines ~247-274)

### 3. Keep Original text for Display/Export

The `text` property with timestamps should be kept for:
- Display in transcript viewer UI
- Export to Markdown/Obsidian (MarkdownGenerator already uses segments with timestamps)
- Any user-facing text that benefits from timestamps

## Benefits

1. **Reduced token count**: Removing timestamp markers reduces ~12-20 chars per segment
2. **Speaker context preserved**: "Speaker 1:" format gives LLM context about dialogue without timestamp overhead
3. **Backward compatible**: Original timestamped text preserved for UI/export
4. **Smart fallback**: Remote endpoints without diarization get raw text automatically
5. **Simple implementation**: Single computed property handles all cases
